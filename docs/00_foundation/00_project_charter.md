# Charte du Projet — Project Dust

> *« Si tout le reste disparaissait, ce document devrait suffire à reconstruire Project Dust sans perdre sa vision. »*

**Version :** Sprint 00  
**Statut :** Vivant (évolue avec le projet)

---

# Pourquoi ce projet existe

Project Dust poursuit deux objectifs.

Le premier est de développer un moteur permettant de jouer à Fallout 2d20 avec l'aide d'une intelligence artificielle.

Le second, et le plus important, est de devenir un meilleur ingénieur logiciel grâce à sa conception.

Le logiciel est le moyen.

L'apprentissage est la finalité.

Si un jour le code disparaît mais que les connaissances acquises permettent de reconstruire un meilleur Project Dust, alors le projet aura rempli sa mission.

---

# Notre vision

Nous ne construisons pas uniquement un logiciel.

Nous construisons :

- une méthode de travail ;
- une façon de réfléchir à un problème logiciel ;
- une architecture durable ;
- une documentation qui explique les décisions autant que les solutions.

Le code est un produit.

Les connaissances sont l'héritage.

---

# Nos valeurs

Nous privilégions toujours :

- la compréhension avant l'implémentation ;
- la simplicité avant la complexité ;
- les besoins réels avant les besoins hypothétiques ;
- la qualité avant la rapidité ;
- les décisions réfléchies avant les solutions improvisées.

Nous acceptons de réécrire du code.

Nous refusons de perdre le raisonnement qui a conduit à son écriture.

---

# Notre méthode

Chaque sprint suit le même cycle.

1. Comprendre le problème.
2. Réfléchir ensemble.
3. Concevoir une solution.
4. Implémenter.
5. Relire.
6. Apprendre.

Le code n'est qu'une étape de ce processus.

---

# La règle du café ☕

Lorsque nous avons l'impression de foncer tête baissée vers une solution...

Nous nous arrêtons.

Nous discutons.

Nous remettons nos hypothèses en question.

Puis seulement nous reprenons le développement.

Réfléchir fait partie du développement.

---

# Notre philosophie d'apprentissage

Project Dust est un projet d'apprentissage avant d'être un projet logiciel.

Chaque nouveau concept doit répondre à un besoin concret du projet.

Nous ne cherchons pas à accumuler des connaissances théoriques.

Nous cherchons à comprendre pourquoi elles existent et quand elles apportent de la valeur.

Les défis, les discussions et les remises en question font partie intégrante du développement.

---

# Notre philosophie d'ingénierie

Nous ne développons pas aujourd'hui des solutions pour des problèmes hypothétiques.

Nous appliquons le principe :

> **YAGNI — You Aren't Gonna Need It**

Nous préférons une architecture simple, claire et évolutive plutôt qu'une architecture complexe anticipant des besoins qui n'existent pas encore.

---

# Le test de la reconstruction

Avant de considérer un document comme terminé, nous nous posons toujours cette question.

> **Si je perdais entièrement le dépôt Git demain, est-ce que ce document m'aiderait réellement à reconstruire le projet ?**

Si la réponse est non, alors le document manque probablement d'informations importantes.

---

# Notre promesse

Chaque sprint doit améliorer deux choses.

Le logiciel.

Et le développeur qui le construit.

Nous ne cherchons pas simplement à terminer un projet.

Nous cherchons à devenir meilleurs grâce à lui.

---

# Nos principes fondateurs

Les connaissances ont plus de valeur que le code.

Documenter le "pourquoi" est souvent plus important que documenter le "comment".

Chaque décision importante doit pouvoir être expliquée.

La simplicité est un choix d'ingénierie.

Une bonne architecture facilite le changement.

Le code est temporaire.

Les bonnes décisions durent.

Nous acceptons de réécrire le code.

Nous refusons de perdre la vision.

Chaque fonctionnalité doit résoudre un problème réel.

Un projet réussi est un projet que l'on peut reprendre des années plus tard sans repartir de zéro.

---

# Notre engagement

Cette charte n'est pas figée.

Elle évoluera avec notre expérience.

Toute modification devra répondre à une seule question :

> **Cette nouvelle règle rend-elle réellement Project Dust meilleur ?**

Si la réponse est oui, elle mérite probablement d'intégrer cette charte.

---

# Citation du projet
