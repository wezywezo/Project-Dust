# Project Workflow

**Version:** Sprint 00
**Status:** Approved

---

# Purpose

Ce document décrit la méthode de travail utilisée tout au long du développement de Project Dust.

L'objectif est de favoriser un apprentissage progressif, une architecture de qualité et un développement durable plutôt qu'une simple production de code.

---

# Core Philosophy

Project Dust est avant tout un projet d'apprentissage.

Le but n'est pas de développer le logiciel parfait dès la première version, mais de construire un logiciel maintenable tout en développant les compétences nécessaires à la conception de logiciels modernes.

Le projet privilégie :

- la compréhension avant l'implémentation ;
- la qualité avant la rapidité ;
- les besoins réels avant les besoins hypothétiques ;
- la simplicité avant la complexité.

---

# Sprint Workflow

Chaque sprint suit le même cycle.

## 1. Discovery

Comprendre le problème.

Avant de chercher une solution, il est essentiel de définir clairement la question à laquelle cette fonctionnalité ou cette décision doit répondre.

Questions :

- Pourquoi cette fonctionnalité existe ?
- Quel problème résout-elle ?
- Existe-t-il une solution plus simple ?

---

## 2. Coffee Break ☕

Moment de réflexion.

Avant toute implémentation, une discussion permet de valider :

- les hypothèses ;
- les risques ;
- l'architecture ;
- les responsabilités.

Cette étape permet d'éviter les décisions prises trop rapidement.

---

## 3. Design

Définir la meilleure approche.

Les décisions importantes sont documentées.

---

## 4. Implementation

Écrire le code.

L'objectif est de produire un code :

- lisible ;
- testable ;
- maintenable.

---

## 5. Review

Chaque fonctionnalité est revue.

La revue ne porte pas uniquement sur le fonctionnement mais également sur :

- la lisibilité ;
- l'architecture ;
- le respect des conventions ;
- la dette technique.

---

## 6. Debrief

À la fin de chaque sprint :

- retour sur les apprentissages ;
- validation des concepts ;
- préparation du sprint suivant.

---

# Learning Strategy

Project Dust est également un parcours d'apprentissage.

Les nouveaux concepts sont introduits uniquement lorsqu'ils répondent à un besoin concret du projet.

Les défis proposés servent à développer le raisonnement plutôt qu'à tester la mémoire.

Les discussions font partie intégrante du développement.

---

# Challenge Philosophy

Les échanges reposent sur un principe simple :

Les décisions doivent être comprises et justifiées.

Chaque règle importante est analysée selon trois questions :

- Que nous apporte cette règle ?
- Quel problème évite-t-elle ?
- Que se passerait-il si nous ne la respections pas ?

---

# Project Philosophy

Le projet n'a pas pour objectif d'être parfait.

Il a pour objectif d'être :

- maintenable ;
- évolutif ;
- agréable à développer ;
- formateur.

Les besoins hypothétiques ne justifient pas une complexité supplémentaire.

Le projet applique notamment le principe YAGNI :

> Ne pas développer aujourd'hui une fonctionnalité qui ne répond à aucun besoin actuel.

---

# Continuous Improvement

Les documents du projet sont vivants.

La méthodologie peut évoluer au fil des apprentissages, à condition que les changements soient discutés et documentés.

L'amélioration continue fait partie intégrante de Project Dust.
